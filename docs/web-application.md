# DataGenome web application — 0.6 local preview

Debug the data, not just the model. The web application connects the existing Python
engines to an owned, review-oriented workflow. It is a pre-1.0 local application,
not an internet-facing production security certification or a promise of improved
model accuracy. Development and verification use no paid services.

## Install and start on Windows

Requirements: Python 3.11+, Node 24 LTS, and a supported Chromium-based browser.
From the repository root, in PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install ".[api,dev]"
npm --prefix frontend ci
.\.venv\Scripts\python -m uvicorn datagenome.api:app --host 127.0.0.1 --port 8765 --no-access-log
```

In a second terminal:

```powershell
npm --prefix frontend run dev
# Or use the optimized build:
npm --prefix frontend run build
npm --prefix frontend start
```

Open `http://127.0.0.1:3000`. `/demo` creates an isolated guest when signed out; when
already signed in, it creates the synthetic project in the current workspace.
The supplied Node wrapper disables Next.js telemetry before starting the CLI.
No external fonts, paid identity providers, analytics SDKs or cloud services are
required. Do not bypass Windows Application Control if a native dependency is
blocked. The verified local compatibility environment used scikit-learn 1.6.1;
hosted Windows CI verifies its own installed dependency versions.

The bridge defaults to `http://127.0.0.1:8765`. Copy `frontend/.env.example` to
`frontend/.env.local` only when a different loopback backend port is necessary.
`DATAGENOME_BACKEND` is server-only and must remain a loopback HTTP URL. Private
environment files are ignored by Git. Python storage configuration is described
in [the security guide](security.md). The Python wheel contains backend modules;
the source distribution also includes frontend source. `node_modules`, compiled
frontend output, local databases, browser traces and private reports are excluded.

## Architecture and integration audit (8A–8B)

Next.js 16.4.6, React 19.3.1 and strict TypeScript provide one application architecture.
TanStack Query manages server state in a layout-persistent provider. Zod validates
project, version, job, session and report envelopes; heterogeneous scientific payloads
retain their versioned backend structures. Native forms, HTML dialogs, tables and
SVG avoid overlapping form/chart/component frameworks. CSS tokens supply dark/light
themes, status colors, responsive layouts and reduced-motion behavior. Lucide icons
are ISC licensed; the application logo, compact icon, wordmarks, favicon, application
icon and social assets are original vector artwork under the project license.

The app shell is loaded separately from the public product page. Scientific fitting,
diagnostic classification, split handling and thresholds stay in Python. The browser
formats actual values and renders bounded tables/charts; it does not reproduce the
scientific algorithms. No artificial dashboard measurements or loading percentages
are supplied. The public preview is generated by `benchmarks/web_preview.py` through
a temporary real backend workspace and is explicitly labeled synthetic.

The typed client in `frontend/lib/api.ts` sends same-origin credentials, keeps CSRF
tokens in memory and preserves structured backend errors. Mutations are not blindly
retried. Job polling is bounded to roughly 1.5–2 seconds and stops at terminal states.
Queue/deadline/cancellation semantics come from actual persisted backend jobs.

### Route-to-API matrix

All `/api/v1` paths below pass through the same-origin bridge and existing backend
authentication/authorization. The bridge rejects non-loopback hosts, cross-origin
requests, invalid path components and bodies above six million bytes, including
chunked bodies. It forwards the verified local origin and CSRF token; backend CORS
and CSRF checks are not disabled.

| Route or workflow | Backend connection | Scope |
|---|---|---|
| `/`, `/features`, `/how-it-works`, `/research`, `/documentation`, `/about`, `/privacy`, `/terms` | Public product/method documentation and generated synthetic preview | No customer statistics or endorsement claims |
| `/login`, `/register` | `/auth/login`, `/auth/register`, `/auth/session`, `/capabilities` | Local usernames; registration respects capability discovery; no fake email recovery/social login |
| `/demo` | `/auth/guest`, `/datasets/demo` | Real owned synthetic project; existing sessions stay in their own workspace |
| `/app`, `/app/projects` | `/projects` | Create, list and search actual owned projects |
| `/app/projects/{id}` | `/projects/{id}/inventory`, project rename/delete | Inventory is paginated, up to 100 artifacts per kind; counts identify the current page |
| `/datasets` and `/datasets/{versionId}` | Legacy `/datasets/profile`, `/datasets`, metadata/configuration/preview/export routes | UTF-8 CSV only, bounded profile/preview, registered split; raw record consent resets per dataset |
| `/analyses` and `/analyses/{analysisId}` | `/analyses`, `/jobs/{id}`, persisted analysis/report routes | Real engine events and optional engine failures; refresh resumes the job URL |
| `/leakage`, `/labels`, `/valuation`, `/fairness` | Selected orchestration engines and detailed analysis responses | Explicit evidence classifications and unsupported states; owner-only detail requires reveal action |
| `/investigation` | Reviewed validation identifiers and the `investigation` engine | Verified binary numeric logistic configuration, contributions, neighbors and measured/inferred relationships |
| `/drift` | `/datasets/drift` | Two explicit bounded CSV files; IID inference disabled; current-view results are not persisted into project reports |
| `/recommendations` | Actual persisted recommendation evidence | View-only dismissal, explicit laboratory review; no automatic application |
| `/experiments` | Intervention preview/apply, bounded search, queued `/experiments`, jobs and results | Exact-plan approval, actual neutral/negative deltas, available bootstrap intervals; outer test remains unscored |
| `/versions` | Inventory, configuration, compare and reviewed reconstruction/export | Real parent/child versions; no overwrite of original data |
| `/reports` | Persisted analyses and report export/delete | JSON, Markdown, engine-status CSV and print-friendly summary |
| `/app/settings` | Session retrieval/revocation and account/guest deletion | Theme, identity, actual limits, retention/privacy information and confirmed deletion |

Use the active dataset/version selector before analysis. Evidence-run selection
allows older analyses to be reviewed after a later engine-only run. Inventory
pagination does not imply complete workspace-wide aggregate statistics. Project
descriptions and last-modified timestamps are not invented when the backend does
not store them. Unknown or unowned resources show an error/empty state rather than
sample user data.

## A complete review workflow (8C–8J)

1. Register/login with a local username and a 12–256 character password, or launch
   the guest demo. Account sessions last up to eight hours; guests expire after one
   hour. Guest workspaces are not merged into registered accounts.
2. Create or open a project. Upload a CSV through the four-stage workflow: transfer,
   backend-computed schema inspection, target/split configuration and explicit review.
   Invalid UTF-8 is rejected rather than silently replacing bytes. Browser limits are
   1 MB for guests or 5 MB for accounts, in addition to backend JSON/row/column limits.
3. Choose supported engines. The UI uses a conservative 30-second cooperative budget.
   Supply group/time columns during registration and sensitive attributes explicitly
   for applicable audits. Submit a real job; inspect actual events and failures.
4. Reveal detailed evidence only in a private environment. The summary does not
   expose labels, record IDs or raw values. A high experimental health score must be
   read alongside coverage and unassessed dimensions. Strong predictive association
   remains a heuristic, and suspected labels are not automatically corrected.
5. For valuation, select a supported method and respect training-record limits:
   LOO 128, exact Shapley/Banzhaf 8, Monte Carlo Shapley 64, numeric KNN Shapley 1,000.
   KNN needs finite numeric features without blanks; the demo intentionally produces
   an unsupported KNN result, while a supported LOO run can generate real values.
   Method- and compute-specific backend guards still apply.
6. Investigate a reviewed validation position under the supported binary numeric
   model. Inspect actual/predicted labels, probabilities, logit contributions and
   related training records. Relationship labels distinguish measured evidence from
   inferred influence. The display shows at most 12 graph relationships, with complete
   results available in detailed JSON. No causal interpretation is promised.
7. Review recommendations, then enter a concrete laboratory plan: selected feature
   removals, stable training-ID exclusions or an explicit replacement label. Preview
   it. Approve that exact snapshot before running or deriving a version. Changing
   fields invalidates the prior preview. No source dataset file is modified.
8. Compare actual validation metrics, per-class outcomes, row/feature changes and
   available uncertainty. A completed computation is not a claim of improvement.
   The experimental Pareto comparison uses balanced accuracy and macro F1; model
   defaults remain fixed in the web laboratory. The held-out test stays unscored.
9. Inspect persisted lineage and compare a derived version with its parent. Export
   reviewed dataset content as `.csv.txt` to avoid automatic spreadsheet formula
   evaluation; source values are preserved. Deliberately renaming/opening such files
   in spreadsheet software can still be unsafe. Engine-status CSV exports contain
   fixed engine/status fields, not arbitrary dataset cells.
10. Export or delete actual reports. Detailed exports may be sensitive; redaction is
    not guaranteed anonymity. Project/dataset/account deletion requires confirmation
    and accurately describes its backend scope. Logical deletion does not guarantee
    physical erasure from backups, journals or SSDs.

## Authentication and client privacy

Server-side ownership remains authoritative. The query provider persists across
routes, but all private state is cleared at identity transitions. The app shell is
keyed by identity, so local forms/previews cannot carry into another account.
BroadcastChannel notifications contain only a change signal; tabs revalidate the
server session and clear prior state. Focus checks provide additional reconciliation.
Expired/revoked sessions return to authentication. Responses and export bodies that
finish after an identity-generation change are discarded. No sensitive tokens,
datasets or reports are stored in localStorage; only `dg-theme` is persisted.

The browser does not add permission sharing, storage encryption, email delivery,
recovery or public deployment. Node and Python must remain local, under a protected
OS account. The same-origin bridge is not a general proxy and does not accept arbitrary
remote backends. See [the complete trust boundary](security.md).

## Verification, accessibility and performance (8K–8N)

```powershell
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend run format:check
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:e2e
python -m pytest
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m build
python -m pip check
```

Playwright starts the real installed Python backend and optimized frontend when
they are not already running; CI requires fresh services. Its separate synthetic
database is `.datagenome/browser.sqlite3`. Do not point it at personal datasets.
Tests use in-app navigation, preserving query deduplication and existing request
budgets. Cancellation, invalid credentials, revocation, cross-user resources, cross-tab
identity changes, CSV registration, predictions, manual corrections, experiments,
exports, lineage and deletion are exercised without mocked scientific responses.

The six requested widths are 360, 390, 768, 1024, 1440 and 1920 CSS pixels. Tables
render 15 rows at a time with controlled horizontal scrolling. Native semantics,
labels, visible focus, reduced motion, screen-reader status messages, captions and
native modal focus/escape behavior are used. Automated axe checks target applicable
WCAG 2.2 AA rules on public/authentication pages and a workspace. This is not formal
accessibility certification or a complete manual assistive-technology audit.

Actual synthetic screenshots are listed in [the screenshot index](screenshots/README.md).
Regenerate the public computed preview with `python benchmarks/web_preview.py`.
Regenerate the social PNG from original SVG with `node frontend/scripts/brand.mjs`.
With production services running, `node frontend/scripts/measure.mjs` writes
[measured bundle, navigation, memory and API data](web-performance.json). Results
are single-run local observations, not fabricated Lighthouse/Core Web Vitals scores
or scalability claims. No isolated chart-render timing is claimed.

Runtime dependencies are MIT/ISC licensed; Playwright is Apache-2.0, and axe tooling
is MPL-2.0. The exact package lock is checked in. ESLint 9 is pinned because the
recommended Next.js plugin set does not support ESLint 10 peers yet; its deprecation
is a maintenance limitation. A previously reported picomatch advisory was withdrawn
by GitHub on 2026-11-18; rescanning the final dependency set reported no known npm
advisories. This is not a claim that the same picomatch version was patched or that
future installations are vulnerability-free. Recheck advisories before deployment.

## Explicitly unsupported or limited interfaces

- No public internet deployment, encrypted database, sharing/organization permissions,
  guest/account transfer, email verification, password recovery or social login.
- Forward-only chronological univariate scoring is supported. No label-horizon purging, predictive proxy
  verification or subgroup intervention confidence intervals. Existing research
  limitations and the HAR independent-evaluation correction remain unchanged.
- The web laboratory uses fixed logistic-regression defaults and the two supported
  Pareto objectives. Advanced SDK model/budget/resampling configuration is not a fake
  enabled UI control. Single-prediction before/after intervention scoreboards are not
  integrated; aggregate experiment outcomes and individual inspections are supported.
- Raw record previews are bounded to 20 records; full-dataset browsing, arbitrary
  correlation heatmaps and unsupported time series are not invented.
- Drift is a separate uploaded-file comparison view, not a persisted project job.
  Recommendation dismissal is current-view state, not a persisted review ledger.
- No standalone PDF generator, individual-version deletion, universal fairness score,
  accuracy-improvement guarantee, or claim of meaningful improvement from a positive
  point estimate. Printer-friendly HTML summaries use the browser's print facility.
- Verification is on Windows and Chromium, with the documented local Python native
  dependency constraint. Other browser engines and internet-scale workloads have not
  been certified.
